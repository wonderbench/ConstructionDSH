# Agent Note: ConstructionDSH 首版开发方案

Status: implemented

[English](2026-09-21-construction-dsh-development-plan.md) | 中文

## 问题

工程人员需要在同一对话中处理 Word、PDF、Excel，按需查询工程规范，并完成安全、质量、造价和进度任务。首版的主要风险不是功能数量不足，而是文件漏读、业务工具混用、金额或日期口径不一致，以及成果无法复核。

本方案落实“先完成再完美”：复用 DSH 及成熟文件库，交付可验证的资料处理和专业成果，不建设完整工程管理平台。后续澄清优先于早期讨论；本文仍是完整交付范围的设计依据，收窄后的首版范围按[最小首版范围说明](2026-09-21-construction-dsh-minimal-first-release.zh.md)交付。

## 决策

**本设计交付：规范 RAG 按需调用、共用文件工具、四个工程业务 Skills、独立图纸拆分流程、可复算的造价和进度工具、侧栏横道图，以及按用户要求生成的 Excel 进度网络图。首版交付最小说明中收窄后的 S1–S7 范围；图纸拆分流程（含 MinerU）、Excel 网络图导出和智慧工地/BIM 接口保持延后，其保留设计见下文。**

### 范围冻结

下表定义完整设计范围；首版实际交付的范围以最小说明为准。

| 编号 | 完整范围要求 | 明确排除或延后 |
|---|---|---|
| F1 | 通过 MCP 灵活查询现有工程规范 RAG，保留原生联网搜索 | 重建 RAG、强制每次检索、自动上传项目资料入规范库 |
| F2 | Word、Excel、轻量 PDF 的共用适配与来源定位 | 所有历史格式和复杂对象的无损转换 |
| F3 | 多份长设计图纸的独立拆分流程，按需接入本地 MinerU | 图纸审查、算量、摘要、变更识别、自动入库 |
| F4 | 安全、质量、造价、进度 Skills 与工具绑定 | 多智能体并行编排和按业务拆微服务 |
| F5 | 基于用户资料的综合单价、报价检查、变更估价和结算差异 | 全国定额库、自动定价、自动投标和自动结算批准 |
| F6 | 分析计算后生成横道图并在侧栏展示 | 已有横道图图像导入还原、拖拽排程、复杂资源最优求解 |
| F7 | 按需生成单代号逻辑网络图 Excel 文件 | 侧栏网络图、双代号或时标网络图、Excel 原生可拖拽节点 |
| F8 | 预留智慧工地/BIM 适配接口、权限字段和 Mock 测试 | 首版真实平台写入、设备控制和全量平台对接 |

工作由一个主智能体和顺序任务阶段完成。四个业务 Skills 为 `construction-safety`、`construction-quality`、`construction-cost` 和 `construction-schedule`；`construction-drawing-split` 工具工作流保持独立。普通文件读取不是第五个工程业务代理。

### 整体处理链

```text
User request + attachments
  -> inspect files and identify task intent
  -> activate one trusted task binding
  -> read only the required content
  -> optionally retrieve standards or public information
  -> validate business data and calculate
  -> create a versioned result
  -> deliver a report / workbook / sidebar Gantt

Explicit drawing-split request
  -> inspect -> optional MinerU structure extraction -> PDF splitting
  -> deliver split files + index + status -> STOP
```

## 仓库落点与复用方式

首版使用仓库的插件、Profile 和 Bundle 机制，不修改 `agent-loop`，不新增绕过 `dsh` 的 Node 应用入口。随附包同时完成依赖、编译入口、文档和测试注册，不只是创建目录。[R2] [R3] [R10]

| 随附位置 | 责任 |
|---|---|
| `packages/construction/construction-runtime/` | Host 工具、任务绑定、文件/造价/排程模块；固定 Python 脚本和锁定依赖放在包内资产目录 |
| `packages/client/ui-construction-gantt/` | 工程成果展示、横道图侧栏、状态显示和本地化文案 |
| `packages/bundle/construction/` | 工程能力组合与显式启用配置；不改变上游默认 Profile 的能力集合 |
| `apps/cli/config/examples/construction/cordis.yml` | 基于已有启动方式的工程示例覆盖配置，经 Loader 测试验证 |
| 各包 `tests/` 与 Skills 资产目录 | 业务模板、输入输出定义、固定样例、异常样例、回归测试 |
| `packages/preset/agent-presets/presets/drawing-split/` | 随首屏模式选择改造以出厂预设形式新增的图纸拆解 Agent 模式 |

仓库现有 `packages/schedule/` 负责定时跟进等智能体任务，不作为施工排程计算器；工程进度计算留在 construction 模块中。[R2]

首版是一个工程功能集合，不是六套服务。内部包遵循仓库命名校验并设置为私有，不向上游组织的包命名空间发布。Python 文件处理器由固定工具通过宿主管理的子进程运行，仓库 `python/` SDK 的用途不变，模型不获得任意 Python 或 Shell 执行入口。

本方案中的工具名、任务绑定字段和成果格式全部作为已实现接口交付；只有引用仓库源码的 DSH 接口属于已核查能力。配置项通过 Schema 校验；文件大小、超时、页批量、图表规模等部署参数不硬编码为不可调整的常量。

## 规范 RAG 与联网搜索

工程行业规范继续由现有 RAG 保存。目标只读能力为 `standards_search` 和 `standards_read`：前者检索规范条款，后者读取命中条款及必要上下文。二者通过当前 MCP 客户端映射到实际服务接口，不要求现有知识库改造成新平台。DSH 的 MCP 工具具有服务器命名空间，连接配置沿用源码接受的传输和字段。[R4]

保留 `web_search`、`web_fetch`，RAG 不作为 Web 搜索替代实现。规范查询、本次附件查询、公开联网查询使用不同入口；普通改写、已明确数据的计算和图纸拆分不强制检索。确需核实公开更新时可联网，但内部附件内容不自动发送到公网。

检索返回规范名称、编号、版本、条款号、内容和位置；地区、适用专业及有效状态有数据才返回，没有就标为未知。命中不等于适用，缺乏依据时输出“依据不足”。先返回少量片段，再按需展开；已注册 Schema 仍有上下文开销，本设计不承诺零 Token 竞争，也不建设动态检索路由系统。

## 共用文件工具与输入质量

### 原件、阅读内容与计算数据分开

原件只读保留。阅读层保留章节、段落、表格及图片引用；计算层保留字段类型、单位、数值、公式及原始位置。不在计算前把所有文件统一转成 Markdown。缓存以文件内容哈希、解析器版本和参数为键，并隔离项目/工作区；内容变化必须重新处理。

统一来源记录使用 `SourceRef`：PDF 为原文件、1 基页码及可用区域；Excel 为工作表和单元格范围；Word 为章节路径、段落或表格位置。未做分页渲染的 Word 不生成页码，只有基础文本的 PDF 不伪造精确区域。提取值、计算值、推断值与人工确认值分别标记。

| 格式 | 工具路线 | 质量要求 |
|---|---|---|
| `.docx` | 原生 OOXML/Word 适配 | 保留正文与表格次序；检查标题、合并/嵌套表格、页眉页脚；发现修订、批注或不支持对象时提示，不静默漏读 |
| `.xlsx` | 原生工作簿适配 | 保留多表、表头、合并区域、隐藏内容、公式和缓存值；不以 OCR 或转 PDF 代替读取 |
| `.pdf` | 轻量 PDF 模块 | 按需读取页、文本、区域或表格；图纸拆分另走专用入口 |
| `.doc`、`.xls` | 独立兼容适配接口 | 以表格/文字内容导入为目标；缺少适配器或内容保真不足时明确提示并要求转换后的副本 |
| 加密、宏或损坏文件 | 检查后明确拒绝或提示处理 | 不破解密码，不执行宏，不把空结果当成功 |

Excel 先做字段映射再计算。清单编码按文本处理；空白不默认等于零；万元与元、百分数与小数、自然日与工作日分别识别；合并区域仅在明确范围内展开；小计/合计不与明细重复求和。只让用户确认影响结果的低置信映射，不要求重新整理整份文件。

openpyxl 不计算公式。[E4] 工具同时保留公式与已有缓存值，不把缓存宣称为本次重算结果。正式业务金额由确定性计算器重算，无法验证的外链或复杂公式列为待核对。导出新文件而不覆盖原件；用户文字安全写为文本，避免以 `=` 等前缀意外产生公式。

工具返回 `complete`、`partial`、`needs_review`、`failed` 等明确状态，并附请求范围、实际完成范围和警告。正文、表格或金额存在关键漏项时不得进入无警告的最终计算。结构检查通过不等于版式、语义或公式正确。

## PDF 双路线

### 日常文件：轻量优先

日常合同、报告、方案、通知和清单默认使用轻量解析。文件多、页数长或轻量提取失败，都不是自动调用 MinerU 的条件。用户指定按页码、每页一份等机械拆分时，直接使用轻量拆页能力，不运行内容模型。

| 依赖 | 固定职责 | 选择依据 |
|---|---|---|
| pypdf | 文件检查、基础文本、复制原页面并拆分 PDF | 成熟页面操作能力；不自行开发 PDF 内核 [E1] |
| pdfplumber | 需要坐标的文本、表格提取 | 面向有文本层的 PDF；不充当 OCR [E2] |
| pypdfium2 | 指定页/区域渲染和拆分质量预览 | 独立页面渲染能力 [E3] |
| 本地 MinerU | 图纸专用流程中所需的结构化拆解 | 保持现有本地部署，只增加薄适配，不成为普通 PDF 的兜底 |

解析器由工具内部确定，模型不自行调用不同库拼凑结果。基础读取不能提取可用文本时，返回 `needs_visual_read`，按需渲染目标页供已授权的视觉模型读取。扫描件批量 OCR 作为独立可选能力，本设计不新增 OCR 服务，更不会自动切到 MinerU。

读取按页批处理，设置内存、时间和输出上限；遇到混合扫描页、乱码、表格断裂或加密分别报告，不用统一“解析成功”掩盖。不为取得一处条款先解析整本，也不凭局部命中声称已审完整本。

### 图纸拆分：专用入口，交付即停止

此路线仅在用户明确要求拆解多份长工程设计图纸，或从受信界面选择图纸拆分任务时开放。工作流先检查原文件和拆分规则；需要结构化结果时调用 MinerU；最终分册 PDF 由 pypdf 复制原始页面生成。MinerU 的内容解析不是 PDF 文件拆页，两项结果分别记录。[E1] [E7] 首版延后此路线：`construction_pdf_split` 只处理机械拆分，结构化拆解请求返回明确的不支持状态。

设计支持按原文件、用户指定页段、每页一份及已有书签边界组织。没有可靠边界时保留原页/明确页段，不让模型猜测专业分册；一页上的多个详图不自动裁开。不栅格化原件再回写，不更改图幅、旋转或比例；若源文件带数字签名，拆分文件不宣称保留原签名有效性。

成果为拆分 PDF、`index.json`、便于阅读的索引表和处理报告，索引记录原文件哈希、原始页码、输出位置、解析器版本和完成范围。MinerU 已有结构化输出可随成果保存，但不自动摘要、审查、算量、识别变更、检索规范或入库；完成后等待用户新需求。

设计只适配部署现场确认的一套 MinerU 版本与真实接口，不同时承诺兼容所有版本；不照抄未知版本的 `/file_parse` 等路径。提交调用快速返回业务 `job_id`，后续查询状态和成果，支持取消；超时不等于底层任务已停止。DSH MCP 客户端的工具超时配置不替代持久化任务管理。[R4]

任务状态写入项目工作区，记录 MinerU 的远端任务标识（如有）。支持恢复时查询原任务，不支持恢复时标为中断并让用户重试，不默默重复提交。重试只处理明确失败范围；覆盖核对须验证每个请求页恰好归属预期输出，用户指定的重叠范围另行标记。

## Skills 内容与工具绑定

### 四个业务 Skills 的内容建设

| Skill | 必需流程 | 成果与禁止行为 |
|---|---|---|
| `construction-safety` | 确认作业/部位和资料范围；按需查规范；核对风险事实、控制措施与缺项 | 问题、依据、来源、建议措施、待核实项；不签发作业许可或虚构安全合格 |
| `construction-quality` | 确认检验对象、样本、单位和适用要求；校验实测值与材料/试验记录的关联 | 资料缺项、数据矛盾、不符合项与复核建议；无检测数据不判定通过 |
| `construction-cost` | 选择单价/报价/变更/结算流程；识别文件用途；映射清单字段；计算或对比 | 分析表、差异表及采用依据；不生成未知价格，不擅自批准或提交 |
| `construction-schedule` | 提取或建立任务、工期、关系和日历；校验假设；排程并生成方案 | 计算结果、工期分析、横道图及按需网络图；不凭缺失逻辑编造关键路径 |

每个 Skill 成套交付 `SKILL.md`、绑定声明、字段字典、输出模板、校验规则和样例。安全与质量分别包含至少一套真实脱敏工作流；造价覆盖四个子流程；进度覆盖新建与调整。每个子流程至少包含正常、缺项、格式异常和依据冲突四类样例，由专业人员确认预期结果。

规范全文继续由 RAG 提供；Skills 保存工作方法而非重复标准全文。字段解释属于业务 Skill，物理文件读取属于共用适配器。技能内容、模板和测试版本一起发布；专业结论必须区分事实、建议、假设和待确认项。

### 绑定由程序执行，不依赖提示词

原生 Skill 调用控制并不等于工具权限绑定。完整设计由工程任务管理器维护宿主可信的 `TaskBinding`，记录任务、Skill 版本、阶段、允许工具和输入类型；不把 `allowed-tools` 等自定义字段写进 `SKILL.md` 就当作 DSH 已执行授权。[R5] [R6] 首版交付轻量形态——每作用域一个活动绑定、重新加载时取代旧绑定、执行器强制执行拒绝——强化管理器保持延后。

完整设计使用 `ctx.tools.restrict(filter)` 缩小继承的全局工具可见性，并用 `ctx.tools.guard(...)` 执行不可被后续监听器放行的拒绝检查。仓库明确说明 restrict 不会隐藏局部注册工具，因此工程守卫和工具执行体同时检查当前任务、文件访问及输入格式。[R5] 这些检查随多智能体编排延后；首版工程 Profile 通过显式禁用承载它们的 base 行来排除面向模型的任意 Shell、代码执行与插件安装（`tool-bash`、`tool-pwsh`、`tool-workflow`、`workflow-ptc`、`ptc-runtime` 携带 `disabled: true`；插件管理工具在 `dsh-base` 中本已禁用）。

工程入口先建立可信任务并加载对应 Skill，再在下一模型步骤开放绑定工具。切换阶段必须等当前调用批次结束，绑定按任务快照执行；不在同批并行工具调用期间累加或切换权限。模型可建议声明过的业务类型，不能传任意工具集合或 `approved=true` 给自己授权；图纸入口还须验证用户的明确意图。

工程模式关闭模型侧任意 Shell、脚本、通用 HTTP、插件安装和能力扩权入口；固定后台脚本仍由工具执行。局部工具、MCP 重连发现的工具、直接调用和后续子调用均受同一规则检查。通用开发 Profile 保持独立，不宣称管理员、用户终端或有宿主机权限的人也被这些业务守卫隔离。

工程 Skills 使用受控只读来源，利用当前本地 Provider 的 `includeDefaultRoots: false` 和明确技能目录，避免工作区同名技能意外覆盖工程流程；其他已挂载 Provider 也须检查，不假设此开关会关闭所有来源。插件卸载或切换任务后释放注册、监听器、连接和当前授权；历史 Skill 文字不恢复权限。[R6]

### 模型工具与绑定清单

模型工具统一使用下划线命名；逻辑模块名可以带点，但 `pdf.read` 等未验证名称不直接作为模型工具。公共能力复用实现，业务工具禁止跨场景调用。

| 工具组 | 入口 | 允许任务 |
|---|---|---|
| 文件只读 | `construction_files_inspect`、`construction_files_read`、`construction_files_search` | 普通阅读及四个业务 Skills；按参数调用 Word/Excel/轻量 PDF，绝不隐式调用 MinerU |
| 机械拆页 | `construction_pdf_split` | 用户明确的拆页任务或图纸流程 |
| 图纸任务 | `construction_drawing_submit`、`construction_drawing_status`、`construction_drawing_result`、`construction_drawing_cancel` | 仅图纸拆分；随图纸流程延后 |
| 造价 | `construction_cost_calculate`、`construction_cost_compare`、`construction_cost_export` | 仅造价 |
| 进度 | `construction_schedule_calculate`、`construction_schedule_present`、`construction_schedule_export_network` | 仅进度；网络导出还需用户请求且保持延后 |
| 成果文档 | `construction_report_export` | 当前业务绑定允许的模板及成果类型 |
| 规范与公网 | 真实 MCP 命名空间下的规范只读工具，以及 `web_search`、`web_fetch` | 有需要的业务任务；不作为图纸拆分后的自动动作 |

## 造价专项实现

四种场景共用清单匹配和确定性计算模块，不建设四套计价系统。输入可以同时包含合同 Word、变更 PDF、清单和报价 Excel；先给文件分配业务用途，再确认清单字段、工程量、价格、费用基数、税口径和舍入方式。

综合单价按每一清单计量单位归一化人、材、机消耗量，先算 `resource_cost = sum(consumption * unit_price)`，再按已明确的费用规则计算。使用十进制固定精度运算；管理费、利润、风险、税费的组成和计算基数来自用户资料或明确设置，不硬套全国通用公式。

| 子流程 | 计算或核查重点 | 输出 |
|---|---|---|
| 综合单价 | 计量单位换算、消耗量、含税/不含税价格、已明确费率与基数 | 单价组成、表达式、计算值和缺项 |
| 投标报价 | 清单匹配、漏项/重复、项目特征和单位、合价与汇总 | 报价差异及需人工确认项目 |
| 变更估价 | 变更依据、增减数量、合同可适用单价或明确新组价方式 | 变更估价明细、方法和依据 |
| 结算审核 | 合同、变更与结算的数量/单价/金额及重复计入 | 审增审减候选、证据和待核实清单 |

保留原始数据、映射关系、计算明细、差异汇总和待确认项。采用的量价费及公式必须能回到来源；一个清单可匹配多个工序，模糊名称不能自动证明同项。缺失价格不从语言模型记忆中补齐，资料不明时输出草案而非正式结论。导出中的权威金额取自冻结的 `CostResult`，不是未计算的 Excel 公式缓存。

## 进度计算与成果生成

### 计算先于绘图

用户要求和附件是分析资料，不是要原样导入显示的横道图。计算模块先形成任务、工期、依赖、日历、里程碑和约束，再生成 `ScheduleResult`。不建设 Excel 涂色识别或 PDF 横道图复刻功能；已有计划表仅作为任务数据来源。

计算器支持单项目工作日历、整工作日工期、完成后开始（FS）关系及明确的非负工作日时距、零工期里程碑、指定开始/完成约束和已完成任务锁定。提前时距、SS/FF/SF、混合资源日历及复杂在建剩余工期算法保持延后；遇到时保留输入并报告，不静默转换为 FS。

校验拒绝唯一任务编号冲突、引用缺失、循环依赖、工期与日期单位错误、日期格式错误和约束冲突，并指明循环。具备完整受支持逻辑时进行前推/后推、时差和关键路径计算；只有日期时只给日期/里程碑偏差，不声称已有网络分析。正在执行的任务采用人工确认的剩余工作作为独立待排任务，防止把历史实际进度重新排掉。

内部使用统一工作时间边界：开始包含、完成边界不包含；正工期任务展示的完成日为完成边界之前的最后工作日，零工期里程碑为一个时点。日期在项目日历中计算，不因浏览器时区改变；图表组件的日期约定通过适配器转换，并用单日、跨周末、跨年和里程碑样例固定行为。

修改请求只创建新方案；原基准与已完成任务不覆盖。输出工期变化、受影响任务、依赖变化、假设和未解决冲突。资源不足时可列建议，但不称为已验证的最优方案；工期计算不替代合同责任、顺延或索赔认定。

### 侧栏横道图

固定客户端组件消费 `ScheduleResult`，采用 Frappe Gantt 并封装 DSH 主题、任务名区域及方案切换。[E5] 模型不生成任意 HTML/JavaScript 图表，图表组件不自动重排业务日期；展示只读，不做拖拽排程。

通过 `ctx.sidebarRightTabs.register(...)`、`sidebar.right.pane.tab` 插槽和 `ctx.sidebarRight.openTab(...)` 接入现有侧栏。它们属于客户端，不是 Host 可直接调用的模型工具。`construction_schedule_present` 返回已持久化的成果标识和展示元数据，客户端成果卡片在当前会话中打开页签；回放历史不自动反复打开窗口。[R7]

| 界面项 | 设计与验收 |
|---|---|
| 工具栏 | 一行显示方案名、日/周/月、适应范围和全屏，不堆多层卡片 |
| 任务区 | 固定名称区，长名称省略并可展开；行与横道严格对齐 |
| 时间轴 | 默认周尺度；长计划切月尺度；表头固定，不无限缩小字号 |
| 样式 | 使用 DSH 主题变量与本地化字典；一个主色、中性灰、有限警示色，状态同时有文字/图标 |
| 空间 | 正文 12–13px、行高 32–36px 可配置；窄栏转紧凑/全屏，不挤成细线 |
| 更新 | 新计算结果生成后刷新；可切换前一方案；切会话不串数据 |
| 状态 | 空数据、计算中、部分完成、假设未确认和失败均有独立提示 |
| 测试 | 420px、720px 侧栏及全屏检查；长任务名、跨月、里程碑及至少 100 个任务样例无遮挡 |

### Excel 进度网络图

Excel 网络图导出保持延后（F7）；以下为保留设计。仅在用户要求网络图时导出，使用与横道图相同版本的 `ScheduleResult` 生成单代号逻辑网络图（任务为节点、依赖为箭头）。没有可靠关系时不虚构网络；双代号和时标网络图明确提示不在范围内，不用普通关系图冒充。

Graphviz `dot` 负责有向图分层布局，openpyxl 将图像与数据写入工作簿；Graphviz 仅负责布局，不计算工期。[E4] [E6] 工作簿包含“网络图”“任务表”“关系表”“说明”四类工作表。节点图为高分辨率 PNG，数据单元格可编辑，图形不是 Excel 原生可拖动节点，改数据后必须重新生成图形。

排版从左到右，节点宽度、间距与字体一致，名称适当换行，编号稳定。主图只放必要信息，详细日期和参数放任务表。关键任务的强调来自计算结果，颜色之外增加线宽/文字图例。外部文字按纯文本转义，不允许通过 Graphviz 标签注入外部文件路径或链接。

默认横向打印，先以可读字号确定页面容量，再决定纸张与分页；不把大图硬缩成一页。按阶段或子网络分到多页/工作表，所有跨页依赖保留目标编号与页签提示。检查中文字形、截断、连线穿节点、打印边界和分页，在实际 Excel 与 WPS 中各做样例确认；可接受环境差异必须标注，不承诺零差异。

## 数据、接口与运行约束

统一结果保存 `schema_version`、`task_id`、输入哈希、采用规则/计算器版本、来源索引、状态、警告和成果文件标识。`DocumentResult`、`SplitResult`、`CostResult` 和 `ScheduleResult` 分别定义，导出器只接受其声明的类型和版本。跨场景交接明确转换，不把任何 JSON 都当成通用结果。

成果写到工作区专用目录，先写临时文件，再校验并发布完成状态；已发布方案只增版本不覆盖。会话日志保存模型可见的调用、结果摘要和定位，文件保存大体量数据。复用普通工具结果与已有文件交付机制，不为进度图引入新的会话存储格式，也不把浏览器 localStorage 当业务数据源。[R2] [R7]

`file_id` 解析到已授权工作区，越界路径、符号链接、大小、压缩包展开量和媒体类型均被检查。解析进程无默认公网访问，密钥不进提示词和成果。项目资料或 RAG 返回仍可能发送至所选模型，因此“本地 MinerU/本地 RAG”不能等同于全链路本地；部署配置须明确模型端点与允许外发的数据类别。

附件、规范片段和 MCP 返回中的文字均视为数据，不能激活 Skill、修改任务绑定或提升权限；任务和图纸 job_id 在每次读取/取消时重新检查工作区归属。

最低运行依赖包括仓库声明的 Node/pnpm、经验证的 Python 环境、固定文件处理库、网络图导出所需 Graphviz，以及按需访问的 RAG/MinerU。锁定实际通过样例测试的版本；启动诊断区分必需依赖和可选依赖，MinerU 离线不阻塞日常 PDF，Graphviz 缺失只禁用网络导出。

## 智慧工地与 BIM 预留

智慧工地/BIM 接口保持延后（F8）；以下为保留设计。它保留最初的平台对接需求，但不使真实平台成为前置条件。预先定义项目/构件/任务查询、问题提案和经审批提交的最小接口，配套脱敏 Mock 与输入输出测试；适配器默认未启用，没有真实凭据时不得返回伪成功。

接口保留 `project_id`、对象标识、来源平台、模型/记录版本、`expected_version` 和幂等键。真实接入阶段由服务器验证用户、项目和操作范围；模型不能自报身份或批准自己的写入。首版不执行生产写入、不直接访问任意 SQL/HTTP，不控制机械或安全联锁。

## 开发顺序与交付物

首版按既定依赖顺序交付各阶段工作包：先交付工程组合、任务绑定、成果类型、样例、文件工具、RAG 配置和业务 Skills；再交付覆盖四个子流程的造价引擎；最后交付 CPM 排程和侧栏横道图。界面使用固定 `ScheduleResult` 样例与后端并行开发。图纸专用入口及其 MinerU 适配、Excel 网络图导出和平台接口 Mock 保持延后，其设计见上文；每个阶段交付可运行的端到端闭环，连同 Skill 内容、模板、样例和文档。

## 考虑过的替代方案

**所有 PDF 都用 MinerU：不采用。**这与日常文件轻量处理和图纸专用拆分的边界冲突，且使可选的本地服务变成所有文件任务的依赖。

**自行编写 PDF 内核或接入大型通用文档平台：不采用。**pypdf、pdfplumber 和 pypdfium2 已覆盖所需基础能力。只建设统一适配、来源定位、质量检查和权限约束；依赖许可证与分发声明在打包前复核。[E1] [E2] [E3]

**为每个 Skill 复制文件工具，或只在提示词声明白名单：不采用。**前者造成重复修复，后者不能阻止执行。共享实现、按任务绑定并由执行器检查，是首版保留的维护与误用控制。

**导入/识别现有横道图、首版支持拖拽和资源最优求解：不采用。**先保证任务分析、可复算排程和固定组件展示。用户通过对话要求调整，计算器创建新版本。

**网络图侧栏编辑器或 Excel 原生连接线系统：延后。**先用自动排版图像与可编辑数据表交付 Excel，明确重新生成要求；需要原生节点编辑或其他网络图类型时另立实现。
