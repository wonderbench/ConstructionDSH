# Agent Note：统一会话状态聚合

Status: implemented

[English](2026-09-21-unified-status-aggregation.md) | 中文

## 问题

待确认事项、会话目标、计划状态、子代理行与后台任务分散在不同区域。UI-IMPROVEMENT-PLAN 的 P4 要求在既有数据源之上提供只读聚合，只展示真实取得的状态——没有总量就不画百分比、不做停止按钮、不把"工具调用结束"等同于"业务任务成功"。

## 决策

聚合扩展既有的 `ui-jobs` 弹层，而不是新增界面：弹层已承载批次 1 的目标切片，且四个真实数据源都能从它的 props 份额直达，零新增注册。

各分区自上而下排列，数据源缺失时整体隐藏：待确认事项居首（标准会话状态座位上最高优先级的 `PendingInteraction`，保持确认事项显著）；随后是当前目标（既有切片）；随后是计划模式（标准 `plan` 投影的 active/pending，折叠口径与输入区计划 chips 完全一致，两处永不矛盾）；随后是目录镜像中的子代理行（模式 chips、标签在缺省时回退到持久 id 并对齐页头谱系、活动词；诊断行经闭联合 `assertNever` 渲染本地化原因词）；最后是既有的有序后台任务行。

方案中的两个字段因无真实数据源而保持省略：工作流状态没有按会话寻址的投影（仅在 `ui-workflow-run` 内有对话事件折叠），成果数量没有投影（`ui-deliverables` 只从对话节点推导按回合数据）。README 记录了它们的插入位置；本切片不虚构任何投影。

子代理行仅在另一个消费者加载目录后才会出现（按契约 ui-jobs 不发起 RPC）；若需要即时填充，那是子代理包的目录加载决策，而非 ui-jobs 的变更。

## 备选方案

**新增侧栏标签或聚合包。** 否决：弹层已承载切片、变更零注册，且符合方案"只读汇总+跳转"的范围。

**在行上增加停止按钮。** 被方案否决：取消涉及模型侧 `job_kill` 契约，需另行立项。

**为补齐字段而新建工作流/成果投影。** 本切片否决：新建 Host 投影超出聚合呈现的范围；数据源落地后字段即激活。

## 后果

弹层容器由列表改为菜单包裹（任务列表保留其列表标签）；新增 16 个本地化键；ui-jobs README 记录了逐分区数据源与两个推迟字段。面板任何位置不出现百分比、停止按钮或伪造的零状态。
